# 客户与Side服务流程

状态：原SOP V1.2的执行流程摘要，已叠加现行V1报价；不是新的完整合同。原件和抽取全文保留在此前整理包中，暂未纳入公开仓库。

运营是订单第一责任人。价格、改期、加时、小酌、退款和异常均由运营统一确认；建群后继续跟进。Side负责现场体验和异常报告。

| 节点 | 运营动作 | 完成证据 |
| --- | --- | --- |
| 社媒获客 | 记录来源平台、具体内容、咨询时间 | 来源记录 |
| 快速需求 | 城市、日期、开始时间、时长、人数、场景感觉、气质；委婉确认客户性别以匹配已确认接单条件 | 简短需求卡 |
| 匹配推荐 | 查档期和条件，每轮2—3位，各给一句理由；旧SOP的10分钟是响应目标 | 候选名单、适配理由 |
| 选定与补全 | Side确认可接，再补区域、饮食等必要禁忌、小酌、交通、拍照和费用 | 接单确认、订单卡 |
| 付款锁档 | 付款前说明预约款和取消规则；预约款金额尚待统一 | 客户确认与到账记录 |
| 三方群 | 介绍运营、客户和Side，明确协调职责 | 建群欢迎、基础订单 |
| 最终行程 | 起止时间、地点、路线备选、费用、参与人数和公开照片权限 | 双方群内确认 |
| 行前 | 前一日和出发前核对天气、交通、场地和状态 | 行前确认 |
| 开始 | 双方见面，记录实际开始时间和预计结束时间 | 群内计时记录 |
| 服务中 | 过半轻量确认；结束前30分钟提醒；收费变化先说明再确认 | 变更记录 |
| 结束 | 确认实际结束、安全离开与已确认加项 | 结束记录 |
| 结算 | 明列基础费、续时、小酌、其他费用与预付款，客户核对后付尾款 | 账单确认与到账 |
| 双向回访 | 分别收集体验匹配、边界、节奏、问题与复购意愿 | 两方反馈 |
| 归档 | 记录付款、时段、变更、反馈和运营复盘 | 全部完成才称已闭环 |

## Side端

入库资料 → 可展示内容核对 → 服务守则与接单培训 → 档期与接单确认 → 行前准备 → 现场执行 → 独立反馈 → 内部结算。分成、补贴归属和付款周期尚待确定。

## 异常与沟通

失约、迟到、体验不适、费用异议由运营介入并分别核对事实；危险时优先保障人身安全。现场不强迫饮酒或身体接触；不私下报价收款。具体退款金额依已确认订单规则，不凭历史建议临场决定。

回访要区分“本人/档案是否一致”和“主观是否合得来”。不把客户私密表达完整转给Side；匿名评价引用需单独确认。

## 与旧SOP的差异

- 去掉订单卡和计费话术中的等级，采用当前228/912/1596/120口径。
- 客户性别可委婉单独询问，匹配时必须核对已确认的接单条件；不按性别差别定价。
- “档案里的照片都是本人近期真实素材”不能用于混有生成图的展示包。可改为“我可以提供已确认可展示的真人参考或本人介绍视频；场景示意图与真实素材会分别注明”。
- 旧SOP第17—18页预约款、取消改期等带有建议性质，仍需统一定稿。
- “3小时行程”可作为候选人访谈题，不代表当前有3小时可计费产品。

可填写物料见 templates/operations.md；它们是执行草稿，不替用户确定待定收费规则。
